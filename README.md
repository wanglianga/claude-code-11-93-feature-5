# 暴雨抢运 · 首轮可执行安排工作台（93-feature-5）

暴雨预警下，调度员只有 **1 吨可用余量**，必须在 **10:00 停止站点装运** 的硬窗口前，给司机一份**当前确实可做的首轮安排**，并明确另一处由谁增援。应用默认打开本题的「暴雨首轮看板」（调度员台 / 司机端两个视角），另可一键进入原有「封路重排」基线工作台。

纯前端应用：React 18 + TypeScript + Vite + Vitest，状态保存在浏览器 localStorage（本题看板）与 IndexedDB（基线工作台），并提供 Docker / Compose 一键启动。

## 本题固定现场与关键数值（09:20）

| 对象 | 数据 |
| --- | --- |
| 天气窗口 | 预警要求 **10:00 起停止站点装运**；到 10:00 仍未**完成清运**即不合规；**赶到站点不算完成**；恰在截止时刻完成算合规 |
| 车辆 V-YJ1 | 额定 2.0t、早班在载 1.0t、**当前可用余量 1.0t**（题目只指定余量；额定/在载为可观察建模） |
| **H 医院站** | 容器容量 1.0t；估计满溢 **80%–95%** = **0.80–0.95t**；截止 **10:00**；现位车程 12 分、作业 8 分 |
| **R 普通街区** | 容器容量 0.7t；估计满溢 **95%–100%** = **0.665–0.70t**；截止 **09:50**；现位车程 8 分、作业 8 分 |
| 传感器 | **两站当前均缺报**；区间来自「前一日实称 + 最近一次有效读数」的带时间估计，页面明确标注**不是 0、不是当前实测** |
| 卸载点 U | H/R→U 均 10 分；卸载 5 分、本例无排队；U→另一站 10 分；之后仍需 8 分作业。**确认卸空后才恢复余量** |

**容量硬事实**：两站估计最低合量 0.665 + 0.80 = **1.465t > 1.0t 余量**，装完首站必须到 U 卸空才能装第二站。

### 逐步时刻推演（页面「逐步时刻推演」卡片原样展示）

- **R 先（满溢率准则的自动建议）**：09:20 出发 → 09:28 到 R → **09:36 完成**（早于 09:50，合法）。
  再 R→U 10 分（09:46）→ 卸 5 分（09:51 确认空）→ U→H 10 分（10:01）→ 作业 8 分 → **H 10:09 完成，晚于 H 截止 10:00 共 9 分钟**。
- **H 先（人工改序 / 等级准则）**：09:20 → 09:32 到 H → **09:40 完成**（合法）。
  再 H→U（09:50 到）→ 09:55 卸空 → U→R 10:05 → 作业 → **R 10:13 完成，晚于 R 截止 09:50 共 23 分钟**。

因此两种排序都**只允许把首站列入本窗口确认任务**；另一站生成「待增援 + 预计失约」，二站线路不得标作可执行，也不提前登记第二站已清。

## 自动建议准则的选择与另一准则的代价

本题**选定「估计满溢率上界优先」**作为首要自动排序键（页面不提供两个策略切换按钮）：

1. 满溢率上界降序：**R 100% > H 95%**，所以自动建议 **R 先**；
2. 上界相同再按稳定站号；
3. 排序之后仍须通过**时间 + 载重硬约束**，硬约束失败的排序第一站会被跳过并说明原因。

**吨位上界 0.70t / 0.95t 只用于容量判断，不参与满溢排序**——两站容器容量不同，直接比吨位会错误地让 H 在前。

**另一准则「敏感服务等级优先」**会让 **H 先**（医院在前；同等级再比满溢率上界，仍相同按稳定站号）。它保护的是**医院 H**：优先保障医疗/敏感服务连续性，降低院感与舆情风险；**代价是让普通街区 R 的居民等待**——而 R 恰是满溢上界最高（100%）、截止更早（09:50）的点，漫溢风险由普通居民承担。本场景下两准则都只能合法完成首站，差别仅是谁拿到唯一确认席位、谁转为增援与失约提示。

**人工改序**：调度员仍可人工指定 H 先，但**必须填写理由**，系统按当前时钟/估计**重新验证时间与载重**；验证不通过时发布按钮保持禁用并列出硬约束原因——人工选择不能越过硬约束。

## 本题验证方式（按步骤点击）

打开 `http://localhost:5173`（或 Docker 的 `:8080`），默认即暴雨调度员台。建议先点一次「↺ 重置现场」。

### A. 核对初始建议、来源与四个关键时刻（无需点击）

1. 顶部时钟为 **09:20**，窗口条提示 **10:00 停止装运**。
2. 「车辆当前载重与可用余量」显示 **载重 1.00t / 额定 2.0t / 余量 1.00t**。
3. 两张站卡均有红色「当前缺报」徽标、黄色「区间来源」说明（前一日实称 + 最近有效读数），吨位分别为 **0.80–0.95t**、**0.665–0.70t**，页面不存在把估计显示成「实测」或填 0 的地方。
4. 准则卡说明「满溢率上界优先：R 100% > H 95%」及另一准则保护 H / 让 R 等待的代价。
5. 推演卡两条时间线分别给出 **R 线 09:36 合法 / 二站 H 10:09 晚 9 分**、**H 线 09:40 合法 / 二站 R 10:13 晚 23 分**，并显示最低合量 **1.465t**。
6. 「待增援」面板已有 **H** 卡片：二站来不及、预计 10:09、晚 9 分钟、预计失约提示；「仍待服务对象」为 H、R。

### B. 发布 R → 司机合法执行 → U 卸空（主路径）

1. 在「③ 确认前核对并发布」勾选**窗口**与**估计修订**两个确认框（未勾时发布按钮禁用）。
2. 确认自动建议为「**首站 R**」，点「确认并向司机发布：仅 R 一站」。
3. 右侧/下方出现已发布卡；H 仍只在「待增援」中，R 变为已派单，**H 没有被登记完成**。
4. 右上角切到「**司机端**」：只看到 R 一个任务与估计区间「非实测」提示。
5. 点「确认到站」→ 顶栏时钟变 **09:28**（提示赶到不算完成）；点「扫描二维码」。
6. 称重框输入 `0.68`（或点「填入合法实称」）→ 提交：提示 **R 于 09:36 完成、合规**，当前载重变为 **1.68t**。
7. 点「R→U 行驶 10 分钟」→ 时钟 **09:46**，页面强调卸前载重仍 1.68t、余量不释放。
8. 点「确认卸空（+5 分钟）」→ **09:51**，载重 **0.00t**、余量恢复 **2.0t**；同卡明确：即便余量恢复，从 U 去 H 仍最早 **10:09**、晚 9 分钟，**不得前往开工**，H 由增援处理。

### C. 人工改序 H（留理由 + 重新验证）

重置现场 → 勾选两个核对框 → 「需要人工改序？」→「人工指定 H 先做」：

- 不填理由时发布按钮禁用，拦截语含「理由」；
- 填写如「医院敏感等级优先」后，实时复验显示「重新验证通过：H 预计 09:40 完成……」，可发布；已发布卡带「人工改序发布」徽标与理由留痕。

### D. 四个演示变异（核对建议失效 / 停收 / 重排 / 仍待服务）

调度员台「演示与验证注入」：

1. **① H 更新为超过 1 吨**：H 估计变 **1.05–1.20t（105%–120%）**，容量复验失败（缺口 0.20t）；建议仍为 R，H 转为红色「硬约束失败」增援卡。此时即便勾选核对、人工强选 H 并填写理由，发布按钮仍禁用，提示人工不能越过硬约束。若此前已发布任务，顶部出现「已发布建议失效：依据发生修订」。
2. **② R 截止提前到 09:30**：R 最早 09:36 完成、晚 6 分钟（09:28 赶到不算），时间硬约束失败；虽然 R 满溢率排序第一，自动建议仍改派合法的 **H**，R 进入硬阻塞增援。
3. **③ 缺报补齐但时间更早**：H 收到迟到补报，明确展示「采样 **08:15** · 接收当前时刻」，且采样早于已采用的最近有效读数 08:40；该报文只作历史补报归档、标记「迟到补报」，**不**外推为当前实测、**不**改变 0.80–0.95t 区间；依据版本递增后两个确认框需重新核对才能发布。
4. **④ 确认后司机实称超限**：重置 → 核对并发布 R → 司机端到站、扫码 → 点「演示④：填入超限实称 1.10t」→ 提交：
   - 红色「**已停收**」提示：1.10t > 可用余量 1.00t；载重仍为 1.00t（不增加），R 不记完成；
   - 切回调度员台：「**已发布建议失效**：实称超限……」，可点「停收/终止原任务并重新排定增援」；
   - R 生成「实称超限」增援卡（本车即便 U 卸空折返，09:28 + 33 分 = **10:01** 才完成，仍晚于 R 截止 09:50 共 11 分钟，须另派车）；
   - 「仍待服务对象」同时保留 **R（停收待援）与 H**。

### E. 10:00 之后只撤离/交接

点顶栏「到 10:00」（或多次 +10 分）：

- 调度员发布区变为「不再发布任何站点开工任务」；发布校验恒为不可用；
- 右侧出现「**10:00 后：仅撤离与交接**」待办，交接明细列出全部未服务站（含估计区间、缺报状态、停收实称），分别可确认；
- 切司机端：出现「停止站点开工」红条与同样的撤离/交接确认，站点开工按钮不再渲染；
- 已完成站的 U 卸空仍可操作（卸载不属于站点装运开工）。
